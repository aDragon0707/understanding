# Lijie A/B Test — 2026-07-24

## 测试目的

比较旧版全局 `lijie` 与 R2 draft 在同一个数学学习任务上的行为差异。

这是单任务、定性、`n=1` 的协议测试，不是统计 benchmark，也不是独立盲评。

## 固定任务

> 我想真正掌握函数可导性的定义。请教我为什么 `f(x)=|x|` 在 `x=0` 不可导，不要只给结论；最后把一个条件改掉，给我一个迁移题。

固定学习者回答：

> 我知道导数像切线斜率，但不明白为什么左右要分开算。

## A 组：旧版全局 `lijie`

### 第一轮行为

- 识别目标为深度理解与迁移，而非摘要。
- 用“切线斜率”直觉引入导数定义。
- 给出差商和左右极限，说明 `h>0` 时斜率为 `1`，`h<0` 时斜率为 `-1`。
- 指出两侧不相等，因此双侧导数不存在。
- 安排检查：解释、比较 `x^2`、诊断一个错误推理。

### 对固定回答的诊断

旧版可以指出“需要分别看左右变化”，但通常把它作为解释中的一个知识缺口；它没有强制形成结构化的状态记录，也没有明确区分 `unknown`、`misconception`、`prompted` 或 `transferable`。

### 代表性输出片段

```text
导数是差商在 h→0 时的极限。对 |x| 在 0 处：
f'(0)=lim(h→0) |h|/h。
h>0 时结果为 1，h<0 时结果为 -1，所以左右极限不相等，导数不存在。

检查：为什么只看 h>0 不够？x² 在 0 处的左右差商各是多少？
```

### 迁移

可给出 `f(x)=x^2` 在 `0` 处是否可导，或要求判断一个分段函数。但迁移与延迟复习属于建议项，不是明确的状态更新协议。

## B 组：R2 draft

### 第一轮行为

R2 先建立学习契约：目标是 `derive + transfer`，成功标准是“能用定义解释、能区分左右差商、能处理条件变化”。随后使用一个最小校准问题，而不是先收集大量背景。

### 对固定回答的诊断

固定回答表明学习者拥有“切线斜率”的直觉，但对单侧极限的必要性存在未验证缺口。R2 将该状态记录为暂时的 `fragile` 或 `unknown`，而不是把流畅直觉当作掌握。

数学适配器会明确拆出：

- `Objects`：函数、点、差商、左右极限；
- `Primitives`：导数定义、极限、正负增量；
- `Operations`：分别令 `h>0` 与 `h<0` 并计算差商；
- `Assumptions`：`h≠0`，并且双侧极限存在才可称为导数；
- `Evidence`：不看原文解释、独立计算、反例和条件变化。

然后只重教“为什么必须同时满足左右极限”，再让学习者预测：`x^2` 在 `0` 处的左右差商各是多少。

### 代表性输出片段

```text
当前状态：有“切线斜率”直觉，但“左右路径必须同时满足”仍是 fragile。
最小修复：导数不是从某一侧靠近的斜率，而是双侧差商极限；任一侧不一致，双侧极限就不存在。

先不要看答案：对 x² 在 0 处，分别预测 h>0 与 h<0 时的差商。
你的下一步证据是：独立计算 + 解释为什么两侧一致/不一致。
```

### 迁移与保持

R2 会改变结构条件，而不只是更换数字，例如：

- 比较 `|x|` 与 `x^2` 在 `0` 处的左右差商；
- 删除“左右极限相等”这一条件，判断得到的对象是什么；
- 对一个分段函数判断连续但不可导、或可导但图像不直观的情况。

掌握请求还会留下一个延迟检索点，而不是在本轮答对后直接标记为长期掌握。

## 结果评分

评分尺度：`0` = 未体现，`1` = 部分体现，`2` = 明确且可执行。单任务人工评分，仅用于发现设计差异。

| 维度 | A 旧版 | B R2 | 观察 |
|---|---:|---:|---|
| 目标与成功标准 | 2 | 2 | 两者都能识别为掌握型任务 |
| 最小校准 | 1 | 2 | R2 把校准设为明确步骤 |
| 数学学科拆解 | 1 | 2 | R2 明确 `Objects/Primitives/Operations/Assumptions` |
| 错误诊断 | 1 | 2 | R2 要求根据回答更新可观察状态 |
| 迁移与边界 | 1 | 2 | R2 将条件变化作为结束标准的一部分 |
| 延迟保持 | 0 | 2 | 旧版没有明确 delayed retrieval 协议 |
| 交互负担 | 2 | 1 | 旧版更轻；R2 多一个校准和状态步骤 |
| **合计** | **8/14** | **13/14** | R2 更完整，A 更轻量 |

## 结论

在这个需要定义、反例、条件边界和迁移的数学任务上，R2 的优势不是“解释得更长”，而是把学科拆解、可观察证据、状态诊断、迁移和延迟保持变成了明确协议。旧版已经能完成高质量解释，且交互负担较低。

R2 的代价是流程开销：对于只想快速知道结论的用户，校准、状态和迁移可能过重。因此 `Depth`、`Interaction` 和 `Verification` 三条轴必须保持可降级，不能每次都强制 Deep + Interactive + Rigorous。
