# 代码学习适配器

本文件用于学习编程语言、API、算法、软件设计和调试。它规定拆解与验证方式，不替代具体语言或库文档。

## 适配范围

优先处理：

- 语言概念、数据结构、算法和控制流；
- API、模块边界、输入输出契约；
- 执行轨迹、调试和错误诊断；
- 从示例迁移到新需求；
- 代码阅读、修改和小型实现。

若用户需要具体版本、近期 API 或高风险安全结论，先查对应官方文档。

## 学科拆解

### Objects

值、类型、变量、状态、函数、对象、模块、接口、资源和外部系统。

### Primitives

语法、表达式、类型规则、控制流、函数调用、数据表示、错误模型和运行时语义。

### Operations

读取、写入、调用、组合、变换、分支、循环、异常处理、编译、执行、检查和部署。

### Representations

根据目标在以下表示之间转换：

```text
需求/行为
→ 最小示例
→ 状态或调用轨迹
→ 代码
→ 测试与运行结果
```

不要只解释语法。说明输入如何改变状态，操作如何产生输出，以及失败路径如何处理。

### Assumptions and Invariants

检查类型、输入范围、资源所有权、状态转换、接口契约、线程安全、时间和空间约束。

### Evidence

根据目标选择：

- 预测一段代码的输出或状态变化；
- 逐步追踪调用栈、变量和异常路径；
- 修改一个输入，预测边界行为；
- 写最小测试或属性；
- 实际执行并检查日志；
- 诊断一个故意植入的错误；
- 在不同需求或规模下实现变体。

## 推荐工作流

```text
需求/问题
→ 最小可运行例子
→ 预测执行结果
→ 运行或追踪
→ 对照差异
→ 定位状态、契约或边界错误
→ 修复
→ 写测试
→ 改变条件再验证
```

对新手优先使用逐步 worked example，再逐渐撤掉提示。对已有经验的学习者减少示例，增加独立设计和迁移。

## 常见错误模型

- 把语法记忆当成运行机制；
- 只看正常路径，忽略异常和边界输入；
- 混淆值、引用、状态和副作用；
- 把局部修复误认为满足整体契约；
- 只依赖测试通过，不检查测试覆盖的行为范围；
- 把一次运行结果当作普遍规律；
- 在没有测量的情况下断言性能或并发安全。

## 迁移任务

改变一个结构性条件，而不只是替换变量名：

- 输入从空值变成极端值；
- 数据规模显著增大；
- 正常路径变成异常路径；
- 接口契约发生变化；
- 单线程改为并发；
- 内存或时间约束收紧；
- 需求增加可测试性、可维护性或可观测性。

## 结束标准

至少有一项来自运行、测试、追踪、错误诊断或独立实现的证据。仅凭“能读懂示例”不能判定已掌握。
