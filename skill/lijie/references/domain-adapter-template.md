# 学科适配器模板

本文件用于为新学科定义“应该拆什么、如何验证、如何迁移”。它不是一份知识百科，也不是要求每次教学都打印的表格。

## 使用方式

1. 先确定学习对象和目标能力；
2. 只填写当前学科真正需要的槽位；
3. 为每个核心对象提供一个验证动作；
4. 为每个常见错误提供一个区分性反例或诊断任务；
5. 为每个重要机制提供一个相邻迁移任务；
6. 将本文件中稳定的学科规则放入独立 reference，避免复制到 `SKILL.md`。

## 适配器契约

```markdown
# [学科名称] Learning Adapter

## 适用范围
处理哪些学习对象？不处理哪些对象？

## 目标能力
解释、使用、推导、证明、实现、批判、创造或保持？

## Objects
该学科操作什么对象、状态或主张？

## Primitives
哪些概念不能删除，否则上层对象失去意义？

## Operations
对这些对象允许哪些变换、行动或推理？

## Representations
具体例子、图示、形式化表达、执行或实验如何互相转换？

## Assumptions
哪些条件必须成立？条件改变时会怎样？

## Invariants
变化或推导过程中必须保持什么？

## Mechanisms
为什么系统会产生这个结果？输入如何改变状态？

## Constraints
方法何时失效？适用边界是什么？

## Failure Modes
初学者常见的错误模型、偷换概念或边界错误是什么？

## Evidence
什么观察可以区分“背过”与“真正掌握”？

## Transfer
怎样改变表面细节或条件，测试底层结构是否保持？

## Prerequisites
需要先掌握什么？如何用一个小问题检查？

## Escalation
什么时候从例子升级到形式化、从提示升级到独立任务？
```

## 选择表示方式

不要默认“具体 → 图示 → 形式化 → 实践”一定是唯一顺序。根据校准结果选择：

- 前置知识很少：先使用 worked example，减少无效试错；
- 有具体误解：先用反例或对比案例制造区分；
- 目标是形式推导：尽早暴露定义、假设和证明义务；
- 目标是执行：尽早让学习者预测状态并实际操作；
- 目标是批判：先区分来源、主张、证据和替代解释。

## 质量检查

- 每个核心对象是否有一个可观察的验证动作？
- 每个机制是否说明输入、状态转换和输出？
- 每个结论是否列出必要条件和一个边界？
- 每个常见错误是否能通过一个任务被诊断？
- 迁移任务是否改变了表面条件，而不是只换了数字或名词？
- 是否误把实例、步骤和理由混在同一层？
