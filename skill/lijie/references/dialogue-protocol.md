# 互动提问、回答路由与证据检索

用于 Interactive/Coaching、多轮追问、补答、更正和恢复上下文。目标是让用户轻松作答，让下一步引导能够回到实际回答。协议降低误路由风险；没有实际记录与检索能力时，不能承诺完整历史可回查。

## 1. 呈现与编号

默认一轮一个核心问题。用户明确要求批量练习时才增加问题数量；同轮问题应能独立作答，依赖尚未回答的问题留到下一轮。根据必要前置能力安排下一轮，无需遍历整张知识树。

```text
❓ **Q1｜先预测**
当 x=3，z=x*x+x 时，dz/dx 是多少？
给一个数和简短理由即可。不确定可以猜，需要帮助就回复“提示”。
```

用 `➡️ **建议**` 表示学习路线、可选动作或作答后的下一步。对尚未作答的检查题，仅提供不泄露解法的建议；用户请求提示或答案时响应并记录帮助程度。用户只想听讲时先提供最小有用解释，不强迫校准。

`Q1`、`Q2` 在同一对话范围内单调递增；分轮不重新编号。内部以 `(dialogue_scope, question_id)` 唯一定位，轮次单独记录。能力对象使用 `skill_id`，重测同一能力仍分配新 question_id。

用户无需输入编号。仅存在多个可能指代且影响反馈时，用一个简短问题确认。Emoji 与文字同时呈现，可按用户偏好省略 Emoji。首次说明“提示、先讲、跳过、换例子”即可，后续仅在需要时提供相关入口。

## 2. 每条消息的处理顺序

### A. 分段与分类

按意义将新用户消息拆为必要片段，一条消息可以同时包含回答、更正和节奏要求。将片段分类为：回答、补答/更正、确认、求助/提示、解释请求、跳过、目标变化或无关补充。只将实际作答片段放入能力证据，确认“懂了”不等于完成检查；“对”若确实回答一道判断题，则按该题作答处理。

### B. 映射到问题

按以下次序寻找目标：

1. 用户明确给出的编号或引用题目；编号不存在时核实，不创建虚假的已问问题。
2. 明确描述的主题或“前面那道梯度题”等指代；检查候选是否唯一。
3. 仅有一道当前题，且片段确实是在尝试作答时，映射到该题。
4. 多候选或确认/作答难以区分时，保持 `ambiguous`，只问必要澄清。能独立处理的其他片段继续处理。

“我不知道”是已关联的困难反馈，可以引导或给提示，但不是正确能力证据。“跳过”记录为 skipped，不解释为答错或不会。新问题先响应，之前未答题保持 pending；只在原目标仍需要它时再继续。

之前 pending 或 skipped 的题收到明确补答时，重新评价并更新状态；不能仅因时间过去或进入下一轮就标记 answered。

### C. 建立可回查证据

保留片段的必要原文和来源引用；再单独写评判与解释。记录是否得到提示、答案是否已经公开、是否独立完成。AI 运行结果属于内容验证，不自动升级学习者能力。

更正创建新的 answer_id，以 `supersedes` 指向明确被更正的记录；原答用于错误历史，当前结论使用更正后记录。只有措辞或主张明确表达替换时才标记 supersedes；同题同条件的回答相互矛盾而更正意图不明时先澄清。补充可以为另一能力添加证据，无需废弃原答。

更正后重查以旧记录为依据的能力判断、未解决缺口和下一步计划；重评相关项，保留无关证据。明确撤回而未给新答案时，将受影响的结论标为待验证，不把撤回当作新掌握证据。

### D. 检索相关记录再生成反馈

先精确定位 question_id 与 skill_id，再读取当前有效回答、其纠正链、必要前置能力证据，以及需要核对的来源片段。语义搜索只能扩大候选，不能代替身份定位和原文核对。

对开放式回答按本题目标与学科标准评判。多重可接受答案应保留，不能仅与一条答案键匹配。资料不足或证明/代码尚未验证时，标记该部分不确定。

完成本轮前检查：本次有意义的片段已路由或保留歧义；能力判断可追溯到真实作答；提示/答案暴露已计入；下一步与本次目标和缺口一致。只展示用户需要的简短反馈。

## 3. 最小问答台账

以下 YAML 仅为一个虚构示例，不是已存储的用户数据，也不证明实际系统具备该存储结构。

```yaml
dialogue_scope: local-session-01
next_question_number: 2
questions:
  - question_id: Q1
    round: 1
    skill_id: gradient_accumulation
    prompt: "x=3，z=x*x+x 时，dz/dx 是多少？"
    goal: "检查能否计入所有路径的导数贡献"
    prerequisites: []
    status: answered       # pending | answered | ambiguous | skipped
    current_answer_ids: [A1]
answers:
  - answer_id: A1
    question_id: Q1
    source_message_ref: local-user-turn-03
    source_kind: local_sequence
    source_excerpt: "我觉得是6，因为x*x的导数是2x。"
    actor: learner
    assistance: none       # none | hint | answer_exposed | unknown
    observation: "给出了6，并计算了乘法项的导数"
    assessment: partial    # incorrect | partial | correct | untested
    interpretation: "可能遗漏加法项贡献，下一题验证"
    supersedes: []
next_action:
  kind: probe              # explain | hint | probe | transfer | clarify | stop
  based_on: [A1]
  target: "检查是否知道+x贡献1"
```

来源优先使用环境提供的真实 message ID 与原文位置。环境未提供 ID 时使用明确标为 local_sequence 的本地顺序引用，并保留足够定位的原文；它不是 API message ID。接续旧台账时沿用其编号，无法确认作用域时新建作用域，避免碰撞。

`current_answer_ids` 指向当前未被替代或撤回的有效作答，可以包含多个互补片段；不得用整个消息替代具体片段的归属。回答是否正确与路由是否明确是不同判断。摘要是检索索引，不替代必要原文。

## 4. 按证据选择下一步

| 当前观察 | 下一步 |
|---|---|
| 原文或回答归属有歧义 | 最小澄清，保留未确认状态 |
| 用户想先听讲或换例子 | 按新要求讲解，相关能力保持未测试 |
| 用户明确不会或前置缺口较大 | 给小型 worked example 或一级提示 |
| 回答部分正确 | 认可成立部分，定位一个缺口，再检查 |
| 独立答对且理由充分 | 进入符合目标的变体，或结束本轮 |
| 提示后答对或答案公开后复述 | 标记帮助程度，换新题检查独立应用 |
| 用户更正前答 | 重新评价更正内容，调整依赖它的后续结论 |
| 达到本次目标、预算结束或用户停止 | 给简短收据与未覆盖范围 |

反馈可以是“你算到了乘法项，末尾 +x 的贡献还没计入”，无需展示全部内部枚举。使用 `✅` 时确认具体完成的动作，避免根据一题宣称整个主题已掌握。异步回复间隔不用于判断能力或情绪。

## 5. 长对话、恢复与持久化边界

当前可用会话内维护紧凑摘要：活动目标、pending 问题、最新有效证据引用、未解决歧义和下一个动作。只保留仍影响目标的记录在活跃上下文中。对重要结论需要原文回查；原文不可访问时说明缺失，不依据摘要虚构旧答案。

写入用户学习数据、跨会话恢复或接入外部存储前，依照用户授权与隐私规则操作。编辑本协议的空白结构或虚构示例，不构成真实学习状态的持久化授权。没有实际文件/MCP/数据库和读取工具时，持久化只是方案，不能声称自动保存或必然恢复。

如果采用真实存储，区分原始作答、不可变证据记录与可更新摘要；更正保留历史，删除或更正个人数据按用户要求处理。恢复时检查当前摘要版本、作用域与证据是否仍可读，不以摘要覆盖用户的新要求。用户不同意存储时继续会话内模式。

## 6. 回归情境与可验证边界

实际行为测试应覆盖：单题无编号作答；多题按编号乱序作答；一条消息回答多题；“对/懂了”确认；补答旧题；明确更正；无更正意图的矛盾；提示后作答；跳过；中途改变目标；未知编号；长对话原文丢失。

检索实现可用校验器检查唯一 ID、引用存在、片段与来源一致、更正链无环和索引版本。自然语言归属、答案正确性与教学判断仍需行为评测和歧义兜底。格式校验通过不能证明 AI 路由无误或学习效果改善。
